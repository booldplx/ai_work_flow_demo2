# STORY-FL-2026-S01-002 · 02 创建预约

迭代 `2026-S01` · Android / iOS · 简体中文

## 用户目标

作为找到合适活动的体验者，我希望在详情预约一席，看到明确的结果，并在返回发现时看到最新余位。

- 需求来源为周末工坊预约 v1.0，验收沿用 B1–B4，B5–B6 为用户确认后补充的验收项。 [产品需求](/Users/laopi/Desktop/Test/周末工坊预约/产品需求.md) · [交互与视觉](/Users/laopi/Desktop/Test/周末工坊预约/交互与视觉.md) · [联调说明](/Users/laopi/Desktop/Test/周末工坊预约/联调说明.md)

- w01 余 3 席且无预约是成功验收基线；w02 为初始满额样例。陈旧状态、响应丢失及重复点击用符合契约的联调或测试场景验证。第 03 卡接通「查看我的预约」实际跳转并验收列表，B4 的预约列表联验对应 C1。

## 验收标准

| AC | Given 前提 | When 操作 | Then 可观察结果 | 页面 |
|---|---|---|---|---|
| B1 | w01 未预约、余 3 席 | 点「预约活动」，服务端返回 201，随后普通返回发现 | 提交期间主按钮显示「预约中…」且禁用，返回可用。成功后留在详情并提示「预约成功」，根据返回的 `workshop` 显示「已预约」、余 2 席。返回发现保留已加载页和滚动位置，对应活动行同时显示「已预约」和「余 2 席」。「查看我的预约」的目的页链路在第 03 卡验收 | P2、P1 |
| B2 | 预约请求在途，或详情所见状态过期且服务端已有有效预约 | 连续点击，或收到 409 / `ALREADY_BOOKED` | 同次提交至多发一笔创建请求。收到冲突时提示「你已预约此活动」，重新读取详情并按最新数据显示已预约，服务端仍只有一笔有效预约 | P2 |
| B3 | w02 满额且未预约，或客户端曾看到余位但此刻服务端已满额 | 查看详情，或提交后收到 409 / `FULL` | 满额且未预约时显示「已满额」，预约按钮不可用。收到冲突提示「名额已满」并重读详情。已有预约时优先显示「已预约」 | P2 |
| B4 | 提交中用户返回，或超时、断线使写入结果未知 | 再进同一活动详情，或使用「重新查询」 | 返回始终可用。结果未知时提供重新查询，查询后按服务端 `myReservationId` 和 `remaining` 恢复状态并同步发现；未知结果期间不会自动重发创建。已成功的活动只保有一笔有效预约，与第 03 卡联验时 P3 无重复记录 | P2、P1；P3 联验 |
| B5 | 用户在 P2 提交预约 | 创建接口返回 404 / `NOT_FOUND` | P2 沿用第 01 卡 A4 的「活动不存在」状态，并提供返回入口 | P2 |
| B6 | 用户在 P2 提交预约 | 创建接口返回 400 / `BAD_REQUEST` | 以 Toast 显示「参数错误」 | P2 |

每次提交预约一席。名额和有效预约由服务端裁决。请求体使用字符串 `workshopId`；`myReservationId` 为可空整数，非空表示已预约。

## 本卡 API 范围

| AC | operationId | Method | Path | 说明 |
|---|---|---|---|---|
| B1–B4 | `getWorkshop` | GET | `/workshops/{workshopId}` | 读取详情和当前预约资格；冲突、结果未知、重新进入时按 HTTP 200 数据恢复 |
| B1–B6 | `createReservation` | POST | `/reservations` | JSON `workshopId`；201 使用 `Reservation.workshop`；409 区分 `FULL`、`ALREADY_BOOKED`；B5 对应 404 / `NOT_FOUND`，B6 对应 400 / `BAD_REQUEST` |
| B1、B4 | `listWorkshops` | GET | `/workshops` | 复用第 01 卡分页接口，后续读取继续以服务端为准；普通返回同步对应活动，保留当前已加载页和位置 |
