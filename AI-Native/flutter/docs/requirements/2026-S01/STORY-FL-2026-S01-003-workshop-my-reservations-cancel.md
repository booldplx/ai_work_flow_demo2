# STORY-FL-2026-S01-003 · 03 我的预约与取消

迭代 `2026-S01` · Android / iOS · 简体中文

## 用户目标

作为已预约工坊的体验者，我希望随时找到自己的预约、查看活动详情，并在计划改变时取消，把名额归还给活动。

## 输入与依赖

- 需求来源为周末工坊预约 v1.0，验收沿用 C1–C4。 [产品需求](/Users/laopi/Desktop/Test/周末工坊预约/产品需求.md) · [交互与视觉](/Users/laopi/Desktop/Test/周末工坊预约/交互与视觉.md) · [联调说明](/Users/laopi/Desktop/Test/周末工坊预约/联调说明.md)
- 依赖 [第 01 卡](STORY-FL-2026-S01-001-workshop-browse-detail.md) 的活动行数据、底栏和共享详情，及 [第 02 卡](STORY-FL-2026-S01-002-workshop-create-reservation.md) 的预约成功状态和联验数据。后端 Story 摘要待提供。
- 持久化验证使用 v1.0.0 模拟服务及同一独立演练数据库。C1 从空库开始，C3 的余 3 席基于取消 w01 的唯一一笔有效预约，C4 分别在预约后、取消后重启服务与 App。

## 验收标准

| AC | Given 前提 | When 操作 | Then 可观察结果 | 页面 |
|---|---|---|---|---|
| C1 | 当前体验者起初无预约，随后预约 w01 成功 | 从底栏打开 P3；从预约成功的 P2 点「查看我的预约」；从 P3 点记录查看详情再返回 | 空库显示「还没有预约 / 去发现」，操作可切回 P1。查看我的预约切换到 P3 根页，原 P2 出栈。P3 展示一笔 w01，记录按创建时间倒序并显示活动信息和已预约状态。点整行用活动 ID 打开共享详情，返回到 P3 和原位置。首载及变更后读取列表，读取失败可重试，已有列表保留 | P3、P2、P1 |
| C2 | P3 有有效预约 | 点该行的「取消预约」，再点「保留预约」、Android 系统返回或关闭确认框 | 行内按钮独立响应，不打开详情。确认框文案为 `取消「活动名」的预约？`，以实际活动名填入，并提供「保留预约」「确认取消」。放弃关闭时发出 0 次取消请求，记录和席位保持原值 | P3 |
| C3 | 发现、详情和我的预约已有 w01 相关状态 | 确认取消，或碰到重复取消、失败及网络结果未知 | 提交中拦截重复请求。204 后移除该条，最后一笔移除时显示空态；重读预约列表和相关活动，发现与详情显示余 3 席及最新未预约状态，并可再次预约。重复取消返回 404 时重新读取我的预约，以读回结果为准。明确失败时保留记录；超时或断线时保留记录并提示刷新确认，按读回结果校准是否取消及活动余位 | P3、P1、P2 |
| C4 | w01 已预约，随后在另一轮完成取消 | 在两个阶段分别重启模拟服务与 App，用同一数据库打开 P3 | 预约后仍能查到 w01。取消后再次重启，P3 为空，恢复结果来自服务端 | P3 |

交互说明建议 P3 使用 `/reservations`。详情导航使用字符串 `Reservation.workshop.id`，取消使用整数 `Reservation.id`。服务端维护有效预约和席位，取消成功后允许再次预约。

## 本卡 API 范围

| AC | operationId | Method | Path | 说明 |
|---|---|---|---|---|
| C1、C3、C4 | `listReservations` | GET | `/reservations` | HTTP 200 读取有效预约 `items`，重切、变更和恢复时以服务端记录为准 |
| C2、C3 | `cancelReservation` | DELETE | `/reservations/{reservationId}` | 只在确认后调用；204 无响应体，404 / `NOT_FOUND` 后重读列表 |
| C1、C3 | `getWorkshop` | GET | `/workshops/{workshopId}` | 从预约行进入共享详情，以及取消后读回该活动的余位和预约状态 |
| C3 | `listWorkshops` | GET | `/workshops` | 复用第 01 卡分页读路径，以最新服务端活动数据核对发现余位，保留位置与已加载页 |
