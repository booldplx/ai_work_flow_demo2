## 2. 路由与返回位置

| 页面 | 路由与入参 | 栈与生命周期 |
|---|---|---|
| P1 发现 | `/discover`，默认入口，无参数 | 保留在发现分支。页面拥有稳定的滚动控制器，发现分支持有列表 ViewModel。 |
| P2 活动详情 | `/workshops/:workshopId`，必填字符串路径参数 | 推入根 Navigator，覆盖底栏。每次打开按路径中的 ID 读取活动。该路由可供后续 P3 复用。 |

- 点击 P1 整行取 `Workshop.id`，例如木匙打磨为 `w05`。View 通过命名路由的 path parameter 传 `workshopId`，路由负责路径编码。P2 解码后交给详情 ViewModel 发起 `GET /workshops/w05`。路径是详情的输入，只带 ID 也能打开。校验非空字符串，ID 格式以契约为准，满额行也可进入详情。一次点击序列只推入一个详情，防止双击堆叠页面。
- 正常路径是 `P1 → push P2 → pop P2 → P1`。按钮、Android 系统返回和 iOS 返回手势走同一个返回栈。P1 在 P2 覆盖期间保持挂载，保留 ViewModel 的 `items`、`nextPage` 与原滚动控制器。列表使用稳定的 `PageStorageKey`，行键使用活动 ID。返回恢复已加载页和原位置，普通返回本身不触发首载或刷新。覆盖期间已在途的追加可更新尾部，偏移保持。
- 直接打开详情且栈内没有来源时，左上返回和 Android 系统返回导航到 `/discover`。iOS 以左上返回作为无栈入口的回退，交互式返回手势用于存在前一页的 push 栈。契约无登录流程。系统级外链注册留给独立入口需求。

## 4. P1 分页状态与并发

ViewModel 以服务端响应作为数据来源，保存当前快照 `items`、`nextPage`、首载阶段、刷新状态、追加阶段及待重试页。布局决定使用滚动触发还是页尾按钮，请求资格最终由 ViewModel 判定。

| 场景 | 触发 | 结果 |
|---|---|---|
| 首载 | 首次挂载发现分支，读取 `page=1&pageSize=3` | 内容区显示加载。成功按服务端顺序展示；`items=[]` 显示「暂无活动」。失败显示「加载失败」及「重试」，重试仍取第 1 页。 |
| 下拉刷新 | 同一纵向滚动区域使用 `AlwaysScrollableScrollPhysics`，短列表和空态也可下拉。回调返回刷新 Future | 暂停追加并保留现有内容，刷新成功用新首页和新 `nextPage` 替换旧快照。主动刷新成功后从页首展示。失败保留原内容、滚动位置、续页及待重试页，在列表顶部显示不占用滚动布局空间的「刷新失败」提示与「重试」，仍可下拉；重试或新刷新开始时收起旧提示。 |
| 正常追加 | 布局完成后随用户向列表尾部滚动，`extentAfter` 进入阈值；ViewModel 验证无在途追加、无刷新、无待重试页且 `nextPage` 非空 | 仅在页尾显示「加载中」。读取服务端给出的页码，按 ID 合并，已有行保持顺序、同 ID 采用新数据，新行按响应顺序追加。原列表及滚动位置保持。 |
| 短列表 | 首屏内容不足一屏且 `nextPage` 非空 | 页尾显示可点击的「加载更多」，与滚动触发共用一个追加入口。布局判定基于标题和列表内容占用的可滚动区域，排除动态页尾自身高度，避免按钮出现后反过来触发自动加载。后续依然不足一屏时继续保留按钮。 |
| 末页 | 响应 `nextPage=null` | 撤掉「加载更多」并关闭自动追加。末页提示的视觉待定。页大小和条数不参与末页判断。 |
| 追加失败 | 当前追加页返回错误 | 保留原列表、位置和待重试页，页尾显示「重试」。点击仅请求该页，失败期间滚动不重发。刷新成功后废弃旧的待重试页。 |

实现取值建议为接近页尾的阈值 **120 逻辑像素**。只有活动页上的用户滚动触发自动追加，首次布局、页尾高度变化和从详情返回均不触发。布局更新后重新计算是否短列表，页尾失败和加载状态优先于「加载更多」。

每次请求从 ViewModel 捕获当前查询代次和本次请求标识。刷新开始即切换代次，取消旧追加并暂停新追加。回调写入前核对代次、请求标识及所有者生命周期，旧页结果即使在刷新失败或成功后抵达也丢弃。刷新失败恢复旧快照，原本被取消的追加页仍可由下一次操作发起。失效请求的完成回调也不能清除新请求的加载状态。滚动与按钮竞争、重复刷新和重复重试均通过同一入口去重。

## 5. P2 详情状态、错误及生命周期

- 进入详情显示加载反馈，返回入口始终可操作。HTTP 200 以响应独立渲染详情。HTTP 404 / `NOT_FOUND` 显示「活动不存在」和返回入口。断网、超时及其他可恢复读取失败显示错误态和「重试」，重试同一 ID。成功体不符合 schema 时进入读取失败态。错误展示不包含响应正文或堆栈。
- P1 区分 HTTP 400 / `BAD_REQUEST`、传输与解析失败，按当前首载、刷新或追加失败态呈现。客户端固定合法页码和页大小，重试走用户操作。一次刷新失败只产生一处提示。
- P1 覆盖时暂停新滚动触发并保留内存快照。P2 出栈时取消该路由在途请求并释放其 ViewModel。P1 真正移除时释放控制器、监听和请求。前台恢复保留当前浏览位置，由用户下拉刷新发现或重试详情，重新进入详情读取新数据。此处保留范围为当前页面会话。
- 列表行惰性构建，布局测量和滚动回调只服务分页。刷新失败提示、页尾加载、详情状态各自局部更新，静态标题与底栏不随请求状态重建。 [错误展示](../../../rules/error-display-conventions.md) · [性能与生命周期](../../../rules/flutter-performance.md) · [状态与存储](../../../rules/state-storage-events.md)

## 6. A1–A4 与 operationId 映射

| AC | operationId | Method | Path（相对 `/api/v1`） | 成功展示 | 失败展示 |
|---|---|---|---|---|---|

| A3 | `listWorkshops` | GET | `/workshops` | 重试对应页，当前请求成功才更新；迟到的旧页无效 | 契约 `BAD_REQUEST` 示例 HTTP 400；传输错误按首载、刷新和追加阶段分别处理 |

按 `WorkshopPage` 的契约顺序展示。首载和刷新显式发送 `page=1&pageSize=3`，追加页号只读可空整数 `nextPage`。P1/P2 基于 `Workshop` 的 `startsAt`、`endsAt`、`title`、`venue`、`remaining` 展示日期、时段、标题、地点和余位，P2 另显示 `description`。日期时间解析后统一按 UTC+08:00 格式化，场次不做过期判断。P1 的 `myReservationId` 非空时显示「已预约」和「余 N 席」，优先于满额标签；未预约且 `remaining=0` 显示「已满额」，其余显示「余 N 席」。
